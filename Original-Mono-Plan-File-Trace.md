# Loading and saving waypoints in the original Mission Planner PLAN screen

Mission Planner 1.3.83 imported a local three-record WPL file in its full desktop interface on Linux/Mono. When the operator accepted the home-position prompt, the planner moved the first record into Home Location, left two waypoints in the grid, and marked H, 1 and 2 on the map. A second, fresh guest repeated the import and saved the plan to a new file. All 36 numeric values survived the round trip. [Imported plan](gui-original-plan-evidence/accepted-home.png) · [Saved plan](gui-original-plan-evidence/roundtrip/save-result.png) · [Saved WPL](gui-original-plan-evidence/roundtrip/saved.waypoints)

## Screen observations

1. DATA opened in the disconnected state. Selecting PLAN opened an empty mission grid and exposed Load File, Save File, Read and Write. Map imagery was unavailable in the offline guest. [DATA](gui-original-plan-evidence/startup.png) · [PLAN](gui-original-plan-evidence/plan.png)
2. Load File opened the file picker. Its panel drew black in this Xvfb capture. The X window tree identified the Open dialog, File name field and Open button, allowing the operator to type the local fixture path. [Picker](gui-original-plan-evidence/load-dialog.png) · [Window tree](gui-original-plan-evidence/load-dialog-tree.txt) · [Input file](gui-original-plan-evidence/input.waypoints)
3. The planner asked “Reset Home to loaded coords”. Three WAYPOINT rows were visible behind the prompt. After Yes, Home Location showed latitude −35.36326, longitude 149.16523 and ASL 584.00. The grid's two remaining rows showed −35.3627, 149.1659 at 23 m and −35.3621, 149.1664 at 37 m. Both had frame 3. The control tree recorded “Loaded plan-readback.waypoints”. [Before Yes](gui-original-plan-evidence/load-result.png) · [After Yes](gui-original-plan-evidence/accepted-home.png) · [Loaded status](gui-original-plan-evidence/accepted-home-tree.txt)
4. The second guest's Save As dialog initially proposed the input filename. The operator selected a fresh output path in its private home directory. The control tree then recorded “Saved plan-saved.waypoints”. Its WPL header, record order and 12 numeric fields per record matched the input. The saved text used additional decimal places, including `23.000000` for the first waypoint's altitude. [Save As controls](gui-original-plan-evidence/roundtrip/save-dialog-tree.txt) · [Saved status](gui-original-plan-evidence/roundtrip/save-result-tree.txt) · [Input](gui-original-plan-evidence/roundtrip/input.waypoints) · [Output](gui-original-plan-evidence/roundtrip/saved.waypoints)

The pinned source assigns the loaded and saved labels in `GCSViews/FlightPlanner.cs` and contains the home-reset prompt. On this disconnected launch the application log says it loaded the ArduPlane command catalogue. This observation therefore establishes a cross-vehicle local file workflow. It leaves connected Copter mode, flight execution, onboard mission transfer, other file types, the No branch and native Windows rendering open. [Application log](gui-original-plan-evidence/release.log) · [FlightPlanner source](mission-planner-1.3.83-source/GCSViews/FlightPlanner.cs)

## Release and replay

Both guests used Mono 6.8.0.105, a private Xvfb display, a fresh release extraction, private home and network namespaces, and a user profile with bundled startup plugins disabled. Neither guest opened a vehicle link. Each post-run archive comparison found all 1,317 release files byte-identical to the portable ZIP and two additional application logs. [Environment and actions](gui-original-plan-evidence/observation.log) · [First extraction](gui-original-plan-evidence/archive-comparison.json) · [Second extraction](gui-original-plan-evidence/roundtrip/archive-comparison.json)
