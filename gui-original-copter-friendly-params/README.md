# Connected Copter CONFIG menu and parameter pages

In a fresh profile, the original Mission Planner 1.3.83 CONFIG menu showed GeoFence, Basic Tuning, Extended Tuning, MAVFtp, User Params, Full Parameter List and Planner. Standard Params and Advanced Params were absent in the screenshot and X window tree. Full Parameter List and Extended Tuning are distinct registrations. This observation establishes the menu for the recorded profile. [First menu capture](sensors-5eLzDluK/config.png) · [Menu tree](sensors-5eLzDluK/windows-config.txt)

The source registers `ConfigFriendlyParams` and `ConfigFriendlyParamsAdv` only when the connection is open, the parameter list is complete and their respective display flags are enabled. The advanced registration also carries the advanced-page flag. Both display flags are false in the constructor, Basic preset and Advanced preset. On loading a saved display view, MainV2 explicitly clears both flags and enables Full Parameter List. This explains why waiting in CONFIG did not produce either target page. Earlier standalone-harness timeouts describe a separate execution path. [Registration gates](../mission-planner-1.3.83-source/GCSViews/SoftwareConfig.cs#L196) · [Basic preset](../mission-planner-1.3.83-source/ExtLibs/Utilities/DisplayView.cs#L340) · [Advanced preset](../mission-planner-1.3.83-source/ExtLibs/Utilities/DisplayView.cs#L427) · [Saved-profile handling](../mission-planner-1.3.83-source/MainV2.cs#L900)

All runs used a disposable Ubuntu-E guest, a private X server and isolated loopback telemetry to simulated ArduCopter V4.8.0-dev (15a10bb4). The release ran under Mono's interpreter, with plugins disabled in the temporary profile. In the initial run, CONFIG displayed Basic Tuning. The return to CONFIG did not finish repainting after navigating to DATA. A second guest logged the Extended Tuning activation, then its recorder exited while reading the changing X window tree. That failed attempt retained a partial tree and no Extended Tuning screenshot or telemetry archive. ## Connected tuning and file browser

In the completed retry, the application logged `MissionPlanner.Controls.MavFTPUI MAVFtp`. The selected page displayed `@SYS Ready` and nine entries, including `threads.txt`, `tasks.txt`, `can0_stats.txt` and `storage.bin`. The first six seconds after selecting the page contain six outbound FTP ListDirectory requests, two for `/` and four for `@SYS`. No file was selected. [File browser](mavftp.png) · [Original application log](release.log) · [Decoded traffic](verification.json)

The next click opened `MissionPlanner.GCSViews.ConfigurationView.ConfigArducopter Extended Tuning`. The directory listing gave way to three columns of numeric controls and several dropdowns. The X tree names the Stabilize and Rate groups for roll, pitch and yaw and a Lock Pitch and Roll Values checkbox. Both the first image and a second capture triggered 54 seconds later show the same partial repaint. Most captions are missing from the pixels and the sidebar still highlights MAVFtp. The first six seconds after selecting tuning include six stream requests and four commands, three REQUEST_MESSAGE (512) and one SET_MESSAGE_INTERVAL (511). The complete retry contains no outgoing PARAM_SET or PARAM_EXT_SET. [Tuning view](extended-settled.png) · [Tuning control tree](windows-extended-settled.txt) · [Selection times](observation.log)

The first completed guest recorded 397 disarmed vehicle heartbeats and the completed retry recorded 336. Each matched all 1,317 files against the release archive. The retry recorder waited an extra 16 seconds before each tuning capture and retried a changing X window tree. Only the recorder changed. [Retry archive comparison](archive-comparison.json) · [Retained telemetry](vehicle.tlog.gz)

## Reproduction

From the repository root, run `python -B gui-original-copter-friendly-params/verify.py --check` to replay saved menu labels, activation records, screen and tree hashes, disarmed heartbeats and click-window traffic.

For a fresh observation in the prepared Ubuntu-E environment, use a separate working copy of the evidence directory to preserve these captures. Run `python3 gui-original-copter-friendly-params/launch.py` from the repository root. Supply the issued run ID to `observe.py` in that directory. The recorded arguments after the ID were `startup 0`, `ready 1 12 12`, `config 2 263 116`, `mavftp 3 145 253`, `extended 4 155 223`, `extended-settled 5 12 12` and `finish 6`. Inspect the current screen before selecting a menu row. Coordinates apply to the recorded 1280×800 display.
