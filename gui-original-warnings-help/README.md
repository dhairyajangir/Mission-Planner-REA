# Help and Warning Manager in the original release

Clicking **HELP** opened the embedded Help page in Mission Planner's main window. It displayed the project credits, keyboard shortcuts, update buttons, console setting and change-log link. The application log identifies the opened control as `MissionPlanner.GCSViews.Help`. The pinned `MainV2.cs` registers this exact type at line 3166 and selects the Help screen at line 4033. This supports original GUI evidence for `mp-module:Help`. The update buttons and external link were left idle. [Help screenshot](help-page.png) · [Help controls](help-controls.txt) · [Application log](release-excerpt.log)

The Help text lists **Control-F – Temp screen**. That shortcut opened the separate `MissionPlanner.temp` tools window. The operator selected its **Warning Manager** button beside “Create custom audio warnings”. The X server then reported a separate 872 × 238 top-level **Warning Manager**. Its nine named child controls were **+**, **Save**, **Item type**, **Field**, **Comparison**, **Trigger**, **Color**, **Message** and **Repeat Interval**. The pinned `temp.cs` creates and shows `MissionPlanner.Warnings.WarningsManager` in `button3_Click` (lines 303–308). The X tree ties the controls to this new form. [Tools window](tools-ready.png) · [Opening window](manager-open.txt) · [Dialog control tree](manager-tree.txt)

The Warnings window interior was black in Xvfb both at its initial size and after resizing it to 890 × 260. The captures establish window creation and control identities for `mp-module:Warnings`. The labels in the Warnings dialog were readable from the X tree only. Rule creation, saving, alert delivery and speech through the GUI remain untested. The [engine](../Warnings-Engine-Trace.md) and [persistence](../Warnings-Persistence-Trace.md) traces cover separate paths. [Original view](manager-open.png) · [Resized view](manager-repaint.png)

## Run and verification

The final session used a fresh extraction of the portable 1.3.83 ZIP, a temporary home, the supported disabled-plugins setting and a private Xvfb display under Mono 6.8.0.105. Its only network interface was loopback. All 1,317 release files matched the archive after exit. Two runtime log files were added. The operator used the toolbar, keyboard shortcut and named tool button. Resizing the existing window was the only follow-up action. [Input actions and runtime](observation.log) · [Profile](initial-user-config.xml) · [Release comparison](archive-comparison.json)

The first navigation attempt also opened the MicroDrone serial-output utility while the Temp menu was painting. That window was incidental, and the isolated guest had no attached serial device. The second attempt opened Warning Manager through its named button but the capture helper could not resize it because the guest lacked awk. The final run used xdotool to select the top-level window directly.
