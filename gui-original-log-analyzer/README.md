# Original Auto Analysis entry point on Mono

Mission Planner 1.3.83 opened its local file picker from **DATA → DataFlash Logs → Auto Analysis**. The operator selected `/evidence/copter.log`. The original application then displayed **Failed to download LogAnalyzer**. After Return dismissed that dialog, a second modal contained **Bad input file**. The first error is legible in the screenshot. The second is recorded in the X window tree while its screenshot shows a black interior. The session ended without an analysis report. [Menu and button](analysis-menu.txt) · [File picker](file-picker.png) · [Download error](download-result.png) · [Second modal](final-result.txt)

The input was the previously retained Mission Planner text conversion of a simulator DataFlash log, 8,267,692 bytes and 140,847 lines. The private guest mounted that file read-only. Its only network interface was loopback. The release log records an attempted download of `LogAnalyzer64.zip`. The 1.3.83 ZIP contains 1,317 release files, with no member named `runner.exe` and no member whose path contains `LogAnalyzer`. All original release files still matched after exit. [Conversion record](../sitl-evidence/nonempty-log-probe/conversion-verification.json) · [Guest and input trace](observation.log) · [Application trace](release-excerpt.log) · [ZIP inventory](release-members.json) · [Post-run comparison](archive-comparison.json)

The pinned `GCSViews/FlightData.cs` handler at line 1299 calls `MissionPlanner.Utilities.LogAnalyzer.CheckLogFile`. The helper requests the runner ZIP and checks for a cached runner when the download fails (`Utilities/LogAnalyzer.cs`, lines 43–74). On a fresh profile this returned an empty path. The caller shows “Bad input file” when the result XML is absent (line 1351). That message alone says nothing about the contents of the selected log. The results form at line 1338 requires XML; this session stopped before that branch.

For `mp-module:LogAnalyzer`, this captures the original GUI entry point and its disconnected dependency failure. The module row names the Python `LogAnalyzer/` directory. Running those scripts or rendering `MissionPlanner.Controls.LogAnalyzer` requires separate evidence. The archived Python 3 run used a modified copy of the analyzer. Run `python verify.py` for the offline evidence check. To repeat the UI run, use `python3 -B run.py` inside Ubuntu-E with the [prepared guest](../gui-original-mono-evidence-20261122/runtime/prepare.sh) and a separate evidence checkout.
