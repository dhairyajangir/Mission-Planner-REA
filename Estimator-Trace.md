# Attitude and position estimation trace

Scope: static inspection of the supplied ArduPilot snapshot at `72b238201f5ea3b556e3809b2ec704fcf701474a`. This follows selected AHRS and EKF3 update paths; it does not validate estimator accuracy or cover all sensor drivers and backend-selection conditions.

`libraries/AP_AHRS/AP_AHRS.cpp:550` updates the inertial sensor unless the caller requests otherwise, updates the configured estimation backend first, obtains its results, then iterates other configured backends. It updates configured and active backend selection, reset counters and published state. Compile-time options control which backends exist. When the active backend changes, it emits a GCS message naming the active backend. The source has a separate fallback location path when its conditions permit; an app should not assume a position field alone proves a particular estimator or sensor source.

`libraries/AP_NavEKF3/AP_NavEKF3.cpp:938` updates each EKF3 core. The code can suppress a core's prediction step when execution time is low, subject to its frame conditions. Its lane-selection logic includes health, error score, armed state, timing and configuration; multiple cores do not imply that every one is eligible for immediate selection.

`libraries/AP_NavEKF3/AP_NavEKF3_core.cpp:645` returns if state initialization has not completed. During an update it selects sensors, reads IMU delta angles and velocities, predicts state and covariance, and invokes fusion-selection routines for available measurements. Some fusion paths are compile-time optional. It then updates status and output states. The actual measurement acceptance checks, innovations, units and failure responses are implemented deeper in those routines and have not been traced here.

The SITL smoke test observed position and attitude messages, and the isolated Mission Planner test copy updated its state to the simulated home coordinates. Neither experiment validated EKF convergence, individual sensor fusion, lane switching, estimator faults, a physical sensor or flight behavior.

## GPS outage in Copter SITL

A standalone client tested the locally built Copter simulator from the archive. With normal arming checks enabled, two arm attempts were denied pending a position estimate; a later attempt armed. After takeoff to a reported 3.428 m and a GPS fix type of 6, the client disabled `SIM_GPS1_ENABLE` for approximately 25 seconds, then re-enabled it. The recorded `GPS_RAW_INT` fix dropped to type 1 and later returned to type 6. This is an induced simulated GPS outage, not a physical receiver test.

During the outage the recorded messages included `EKF3 lane switch 1`, `EKF variance: position lost`, and `EKF Failsafe: changed to Land Mode`; a heartbeat reported LAND while armed. The simulator later reported ground contact and motor disarming. After GPS was re-enabled, it reported both EKF cores using GPS, a recovered fix, and `EKF Failsafe Cleared`. The script then requested LAND and observed a disarmed heartbeat. Because disarming was reported before GPS was re-enabled, the run does not establish in-flight recovery. Source at `ArduCopter/ekf_check.cpp:49` checks for a position estimate and accumulates failed checks; `:166` selects the configured EKF failsafe action. The observation does not establish estimator accuracy, exact timeout, behavior with different sensor configurations or real-flight safety.

The full event record is `sitl-evidence/archive-copter-gps-loss/results.json`; `transition-summary.json` deduplicates repeated fix, heartbeat and EKF-status values while retaining status messages. Its times are local message-arrival times relative to harness startup, not precise fault-injection or aircraft-state timestamps. The source hash and nine test checks are retained in both artifacts.

A second run restored the simulated GPS about three seconds after the disable parameter was confirmed. Following takeoff to a reported 3.433 m, its GPS fix dropped from type 6 to type 1 and returned to type 6 after re-enabling the sensor. The next relevant heartbeat showed the simulator still armed in GUIDED; the client then requested LAND and later observed disarming. No `EKF Failsafe: changed to Land Mode` notice appeared in the captured status messages. The observations and deduplicated transitions are in `sitl-evidence/archive-copter-gps-short-loss/`. This is one short simulated outage with one set of defaults; it does not establish the duration that other aircraft or configurations can tolerate.
