# Copter sensor and radio pages in the original Mission Planner window

Mission Planner 1.3.83 ran on Linux/Mono with a fresh user profile and its startup plugins disabled. The profile connected to a disposable ArduCopter 4.8.0-dev quad simulator on loopback in the same isolated namespace. Navigation opened seven setup pages and the Mandatory Hardware and Optional Hardware group pages. The application log records the nine corresponding WinForms types. The initial and final Flight Data screens both showed DISARMED. All 518 recorded heartbeats from the simulated quad agreed. ## Parameter traffic during navigation

The operator clicked only menu entries, the navigation scrollbar and the Flight Data tab. Opening the primary Battery Monitor was followed by a parameter write. Before this page opened, a vehicle PARAM_VALUE record at 19:08:22.224 UTC reported BATT_VOLT_MULT as 10.100000381469727. The page click occurred at 19:13:01. At 19:13:04.238 the ground station sent PARAM_SET with that same value, and the vehicle echoed it at 19:13:04.250. The application log records both actions. This was the only outbound PARAM_SET in the retained telemetry. About ten seconds later the ground station sent MAV_CMD_PREFLIGHT_STORAGE with its first argument set to 1. The capture does not establish which callback initiated either command or whether the value persisted across a restart. No calibration or motor test was requested by the operator. ## Provenance and replay

All 1,317 files from the portable release ZIP matched their extracted counterparts after the session. The application added three log files in that disposable directory. The capture identifies the simulator binary by SHA-256, records the guest network interfaces and retains the starting profile. The radio values and battery state here belong to this simulation. The Mono renders cover a single session and screen size. Native Windows rendering, calibration outcomes and changed-setting behavior remain open. [Archive comparison](gui-original-copter-sensors/sensors-FjBlM50a/archive-comparison.json) · [Guest and navigation log](gui-original-copter-sensors/sensors-FjBlM50a/observation.log) · [Starting profile](gui-original-copter-sensors/sensors-FjBlM50a/initial-user-config.xml)

Run `python -B gui-original-copter-sensors/verify.py --check` from the repository root. The replay checks frame boundaries and relevant MAVLink checksums, verifies the quad never reported its armed flag, and brackets each reviewed page with disarmed heartbeats around the click and four-second capture delay. Each reviewed screenshot and its matching window tree has a recorded SHA-256. A new GUI session can use the existing guest environment with `bash research-tools/observe-original-copter-sensors.sh --copter` inside Ubuntu-E. The capture retains its own copy of the guest script.
