# GPS altitude points in the Copter Log Browser

The Mission Planner 1.3.83 Log Browser produced 391 points for `GPS[0].Alt` from the archived Copter simulator log. A direct read of each GPS record in the binary file matched every plotted altitude on both axis settings. The first point was 578.12 m. The remaining 390 were 584.09 m. With **Line Number** selected, all 391 x coordinates matched the zero-based record numbers, from 10,979 to 140,792. [Captured curve points](sitl-evidence/copter-log-gps-graph/points.csv) · [Binary input](sitl-evidence/nonempty-log-probe/downloaded.bin)

The first GPS record had status 1. The second had status 6 and supplied the time anchor, 05:22:17.800 UTC on 4 November 2026. The earlier record also appeared on the time axis. For each sample the independent verifier reconstructed the timestamp from the GPS week and milliseconds of week at the anchor, the logged boot time in microseconds, and the release's whole-millisecond anchor offset. It compared that timestamp with the chart's numeric date at the recording machine's UTC+05:30 offset. The difference across all 391 points ranged from −36 to +41 microseconds. A fresh process produced the same bounds. [Comparison and hashes](sitl-evidence/copter-log-gps-graph/verification.json)

The offline probe created the release's `LogBrowse` form with a hidden handle, set map access to cache-only, opted out of tracking, and supplied its `DFLogBuffer` with the existing local file. It called the chart worker `GraphItem_GetList` for GPS, Alt, instance 0 with no modifier. The worker invoked the release's own `GraphItem_AddCurve`. The probe captured coordinates from the resulting ZedGraph curve after each axis selection. Its first attempt stopped before graphing because the probe looked up `DFLogBuffer.dflog` as a field. Using the release property's getter fixed the harness. This is instrumented Windows form execution. It exercises the data and plotting methods, leaving visible rendering, menu navigation and other graph fields open.
