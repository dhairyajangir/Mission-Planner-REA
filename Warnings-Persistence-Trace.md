# Warning rules survive a fresh engine process

Mission Planner 1.3.83 saved a compound battery warning to XML and restored it automatically in a second process. The fixture used synthetic voltage and armed-state properties. Both processes loaded the portable `MissionPlanner.Utilities.dll`. Its bytes matched the DLL in the release ZIP. [Assembly and evidence hashes](warnings-persistence-evidence/sha256.json)

The first process set the application's custom user-data directory to a fresh temporary profile. The engine began with an empty rule list. The probe added a gold colouring rule for voltage below 10.75, a 30-second repeat interval, and a child condition requiring the armed flag. It called the engine's own `SaveConfig`. The resulting XML escaped the literal less-than and ampersand characters in the message template. [Writer observations](warnings-persistence-evidence/save.txt) · [Saved warnings.xml](warnings-persistence-evidence/warnings.xml)

The second process installed the same synthetic property source before first accessing the engine. Its initial rule list already contained the parent and child. Their field names, comparisons and thresholds survived, along with the parent's colour, repeat interval and message. At voltage 9.5 with the armed flag set, both comparisons returned true. Clearing the flag changed the child result to false. Raising voltage to 11.25 then changed the parent result to false. The probe called the loaded rules directly. The warning dialog, live telemetry, timed dispatch and speech remained outside this run. [Reader observations](warnings-persistence-evidence/load.txt)

The initial probe build stopped with compiler diagnostic CS0012 because the portable DLL references .NET Standard. Adding the installed Framework's `netstandard.dll` reference made the probe compile. To repeat on Windows, run `python research-tools/run-warnings-persistence.py <new-output-directory>` from the research repository. The runner creates separate writer and reader processes and removes their temporary profile after copying the evidence. [Runner](research-tools/run-warnings-persistence.py) · [Probe](research-tools/WarningsPersistenceProbe.cs)

The earlier comparison probe independently supplied NaN and a nonnumeric string to the rule evaluator. Six comparisons with NaN returned false and `NEQ` returned true. Converting the string-valued field raised `FormatException`. These are captured invalid-input tests under the matrix definition of `fault_injected`. They used the data-redirected assembly identified in the earlier trace.
