# Battery percentage on the Mission Planner 1.3.83 HUD

The release HUD drew `Bat1 12.25v 3.0 A 0%` for both an unavailable primary estimate and an empty primary battery. Those two captures were pixel-identical. The earlier packet test explains the shared result: the primary state setter converts the MAVLink unknown value −1 to zero before the HUD reads it. [Unknown primary](mission-planner-gui-faces/battery-hud/primary-unknown.png) · [Empty primary](mission-planner-gui-faces/battery-hud/primary-empty.png) · [Packet transitions](Copter-Battery-Remaining-Trace.md)

The secondary battery behaved differently. With both battery lines enabled, icons off, cell-voltage display off and a positive secondary voltage, the second line showed `Bat2 11.40v 2.0 A -1%` for unknown and `Bat2 11.40v 2.0 A 0%` for empty. The primary line continued to show 78% in both cases. [Unknown secondary](mission-planner-gui-faces/battery-hud/secondary-unknown.png) · [Empty secondary](mission-planner-gui-faces/battery-hud/secondary-empty.png)

At zero secondary voltage, only the primary line appeared and the unknown/empty secondary pair had identical pixels. Enabling the icon layout at positive secondary voltage also produced identical images for that pair: the control drew a battery icon and the primary voltage, current and percentage. [Zero secondary voltage](mission-planner-gui-faces/battery-hud/secondary-no-volts-unknown.png) · [Icon layout](mission-planner-gui-faces/battery-hud/icons-secondary-unknown.png)

## Capture and replay

The probe used the shipping `MissionPlanner.Controls.HUD` software renderer on Windows, with an 800 × 480 drawing surface, English UI strings and invariant numeric formatting. The cases shared one release `CurrentState` object. For each case, the probe set its two percentages and copied the resulting properties to a freshly constructed HUD, following the two bindings declared in the designer. The probe invoked the control's `doPaint` method and saved its lower-left 310 × 70 pixels unchanged. An independently compiled repeat produced byte-identical copies of all nine PNGs and the six-comparison result. The comparisons include a positive control in which the primary percentage changes from 78% to zero. Full Flight Data window binding, OpenGL rendering, threshold alarms and hardware remain untested. [Designer bindings](mission-planner-1.3.83-source/GCSViews/FlightData.Designer.cs) · [Probe](research-tools/CopterBatteryHudProbe.cs) · [Pixel comparisons and hashes](mission-planner-gui-faces/battery-hud/results.json)

Run `python research-tools/run-copter-battery-hud.py <new-output-directory>` on Windows with Pillow installed. The runner extracts assemblies from the retained portable ZIP into a temporary directory. No telemetry interface is opened. [Replay program](research-tools/run-copter-battery-hud.py)
